## Shape descriptions

- **`php-open-tag-counts-branch`** — branch +1 per `<?php`/`<?=` open tag (ternary-? alternation matches the tag) (languages: php)
- **`go-import-counts-bypass`** — safety_bypasses +1 per quoted import (dot-import alternation's dot is optional) (languages: go)
- **`cobol-hyphen-identifier-debt-leak`** — fragile/planned_debt counted inside hyphenated identifiers (BUG-COUNT, WS-FIX-FLAG) (languages: cobol)
- **`css-hyphen-identifier-debt-leak`** — same leak shape in css class names (.bug-icon, .todo-list) (languages: css)
- **`kotlin-return-in-branch`** — branch +1 per return statement (6-language family; kotlin shown) (languages: kotlin)
- **`solidity-return-in-branch`** — branch +1 per return statement (6-language family; solidity shown) (languages: solidity)
- **`string-literal-branch-keywords`** — branch keywords inside double-quoted literals (phantom flux trigger candidates) (languages: python, javascript, c, ruby)
- **`swift-open-api-fp`** — api-exposure from the bare word `open` outside declaration position (languages: swift)
- **`html-script-func-start-unreachable`** — script/style tags whose func_start credit is silently lost end-to-end (languages: html)

A shape at ~100% of files (php open tag, go imports, return-counting) is a constant per-file bias — it shifts every score in that language uniformly. A sparse shape (debt-in-identifiers) is a per-repo hazard — invisible until it isn't. Both kinds are already baked into every real scan GitGalaxy has ever produced for these languages; fixing the filed issues re-baselines them.
